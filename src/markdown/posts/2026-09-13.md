This post outlines how to set up Grok Build on an AWS EC2 Linux instance for isolation, connect to it using SSH, then pull project deltas to your local machine for testing.

**Note**: This guide is a reminder to myself on how to do the setup, but it was largely compiled with Grok.

**Important**! This method leaves off the use of SSH password, using the AWS key only. 

The purpose is to give Grok access to the files and executables of an operating system that is not your personal one to help minimise security risks and file losses.

Requirements (i.e. areas this post does not cover):
* AWS account with payment method **[https://docs.aws.amazon.com/accounts/latest/reference/manage-payment-method.html](https://docs.aws.amazon.com/accounts/latest/reference/manage-payment-method.html)**.
* Understand how to create an AWS security group and keypair.
  - **[https://docs.aws.amazon.com/vpc/latest/userguide/creating-security-groups.html](https://docs.aws.amazon.com/vpc/latest/userguide/creating-security-groups.html)**
  - **[https://docs.aws.amazon.com/batch/latest/userguide/create-a-key-pair.html](https://docs.aws.amazon.com/batch/latest/userguide/create-a-key-pair.html)**
* Create an x.AI account and get credits or a subscription for an API key **[https://docs.x.ai/developers/pricing](https://docs.x.ai/developers/pricing)**.

```
Local machine (openssh)
    │  ssh to grok-build
    ▼
Ubuntu (AWS EC2 instance)
    ├── run grok
    └── ~/projects/myapp
    │   rsync / scp
    ▼
Local machine
    └── ~/Projects/myapp
```



## Step 1. Create an Ubuntu AWS EC2 instance

* Create your AWS instance with these parameters (requires security group and key pair to already be created)
  - Name: grok-build
  - AMI: Ubuntu Server 26.04 LTS (HVM), SSD Volume Type -- Free tier eligible
  - Instance type: t3.small (2GiB memory) -- Free tier eligible
  - Key pair name: your-keypair
  - Select existing security group: your-security-group
  - Configure storage: up to 30 GiB -- Free tier eligible

The instance should be launched and running.
Make note of the Public IPv4 address.

![AWS EC2](/src/assets/blog/2026-09-13--01.png)



## Step 2. Check your local machine for the needed tools

* These are the tools:
  - `ssh` Secure Shell - Use an encryted connection to a remote computer.
  - `scp` Secure Copy Protocol - Copy files between computers using SSH encryption.
  - `rsync` Remote Sync - Copy and synchronise files and directories.

* From your local machine, check that the above tools are available (for Linux). Note that scp is bundled with ssh.
```
ssh -V; rsync --version | head -n 1
```
  - If they are not, then install them.
```
sudo dnf install -y openssh-clients rsync
```

![AWS EC2](/src/assets/blog/2026-09-13--02.png)



## Step 3. Create an SSH key directory

* From your local machine, create and restrict permissions to the ssh key directory so only the owner has access.
```
mkdir -p ~/.ssh
chmod 700 ~/.ssh
```

* Place your key pair's .pem file into that directory and modify its permissions so only the owner can read it.
```
chmod 400 ~/.ssh/your-keypair.pem
```

![AWS EC2](/src/assets/blog/2026-09-13--03.png)



## Step 4. Create a configuration file for daily SSH access

* From your local machine, create the configuration file.
```
nano ~/.ssh/config
```

* Add content to the configuration file.
```
Host grok-build
  HostName <EC2 instance's Public IPv4 address>
  User ubuntu
  IdentityFile ~/.ssh/grok-build.pem
  IdentitiesOnly yes
  ServerAliveInterval 60
  ServerAliveCountMax 3
```

* Update the configuration file's permissions so that only the owner can read and write to it.
```
chmod 600 ~/.ssh/config
```

![AWS EC2](/src/assets/blog/2026-09-13--04.png)



## Step 5. Install Grok on the AWS EC2 instance

* From your local machine's terminal, make the first connection using SSH.
```
ssh grok-build
```

* You will be prompted with a warning,type `yes` then Enter.
```
Are you sure you want to continue connecting (yes/no/[fingerprint]
Warning: Permanently added <your Public IP address> to the list of known hosts.
```

![AWS EC2](/src/assets/blog/2026-09-13--05.png)
  
* From your EC2 server, run these commands to update the server and create a projects folder.
```
sudo apt update
sudo apt upgrade -y
sudo apt install -y curl git build-essential tmux unzip ca-certificates
mkdir -p ~/projects
```

**Note**: `tmux` keeps Grok alive if your local achine sleeps.

![AWS EC2](/src/assets/blog/2026-09-13--06.png)

* From your EC2 server, install the Grok Build client.
```
curl -fsSL https://x.ai/cli/install.sh | bash
source ~/.bashrc
grok --version
```

* From your local machine, log into **[https://console.x.ai](https://console.x.ai)** in a browser. This will be used to approve account authorisation for the EC2 server.

* From your EC2 server, initiate the Grok device authorisation request (does not require an API key)
```
grok login --device-auth
```
  - Provides a URL. Copy it. 
  - From your local machine, paste that URL into your browser and authenticate the device i.e. the EC2 server.
  - **Note**: At time of writing, there is no way to de-authorise devices from the x.AI console. It is only possible by logging out from the device itself using `grok logout`.

* Alternatively use an API key.
```
echo 'export XAI_API_KEY="xai-your-key-here"' >> ~/.bashrc
source ~/.bashrc
```

![AWS EC2](/src/assets/blog/2026-09-13--07.png)



## Step 6. Create a Projects folder on your local machine

* From your local machine create a Projects folder that will synchronise with the EC2 instance.
```
mkdir -p ~/Projects
```

## Step 7. Daily use of Grok Build

* From your local machine, connect to the EC2 instance.
```
ssh grok-build
```

* From your EC2 instance, open `tmux` terminal and navigate to your project folder or create a new one, then connect to Grok
```
tmux new -s grok
cd ~/projects
```
  - Create a new project.
```
mkdir -p myapp
cd myapp
```
  - Clone a GitHub project.
```
git clone https://github.com/makuharistudio/makuharistudio.github.io
```
  - Run Grok Build.
```
grok
```

![AWS EC2](/src/assets/blog/2026-09-13--08.png)
    
  - Exit (not log out) of Grok Build by pressing Ctrl + C twice.

* If SSH connection drops.
```
ssh grok-build
tmux attach -t grok
```

* From your local machine, synchronise the project in the EC2 instance to your local copy.
  - Open a separate second terminal or terminal tab.
```
rsync -avz --progress grok-build:~/projects/makuharistudio.github.io/ ~/Projects/makuharistudio.github.io/
```
  - Swap it the other way around to upload files from your local copy to the EC2 instance.
```
rsync -avz --progress ~/Projects/makuharistudio.github.io/ grok-build:~/projects/makuharistudio.github.io/
```

* From your local machine, alternatively, copy a single file using the first SSH terminal session.
```
scp grok-build:~/projects/myapp/README.md ~/Projects/myapp/
```

* Log out of Grok from the device. For example, if shutting down the machine. Requires `grok login --device-auth` to work again.
```
grok logout
```

* Disconnect the SSH session.
```
logout
```
